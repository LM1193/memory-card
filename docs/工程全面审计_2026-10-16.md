## 二、🔴 P0 级 — 必修，否则无法交付

### P0-1 · 构建场景列表指向的是空场景，不是你的主场景

**证据** `ProjectSettings\EditorBuildSettings.asset`：

```yaml
m_Scenes:
- enabled: 1
  path: Assets/Scenes/SampleScene.unity      # ← 这是那个只有 Main Camera 的空场景
  guid: 2cda990e2423bbf4892e6590ba056729
```

`Assets\Main.unity`（你真正搭好全部内容的场景，43 KB）**根本不在构建列表里**。

**后果**：一旦 Build（WebGL 或 Windows），打出来的包加载的是空场景 → 打开就是**一片纯色、什么都没有**。这是最容易在最后关头才发现、也最冤的坑。

**修复**
1. 菜单 `文件 File` → `生成设置 Build Settings…`（快捷键 `Ctrl+Shift+B`）
2. 在 `生成中的场景 Scenes In Build` 列表里，**取消勾选** `Assets/Scenes/SampleScene.unity`（或选中它点 `移除 Remove`）
3. 先在层级里打开 `Main.unity` 场景，然后点 `添加打开的场景 Add Open Scenes`
   （或从项目窗口把 `Assets/Main.unity` 直接拖进这个列表）
4. 确认列表里 `Assets/Main.unity` **有勾**、且**排在第 1 位**（左边的序号是 0）
5. 关掉窗口

> 建议顺手把 `Main.unity` 从 `Assets\` 根目录移到 `Assets\Scenes\` 下（在项目窗口直接拖）。Unity 按 guid 追踪引用，移动后 Build Settings 里的记录不会丢。

### P0-2 · WebGL 构建模块根本没装（Hub 却显示"已安装"）

**证据** `E:\Unity Hub\2022.3.62f3c1\Editor\Data\PlaybackEngines\` 下**只有**：

```
windowsstandalonesupport      ← 只有 Windows 桌面
```

全盘搜索 `WebGLSupport` / `UnityLoader.js` / `*.jslib` —— **一个都没有**（只找到 `il2cpp/libil2cpp/os/Emscripten`，那是基础编辑器自带的源码目录，与 WebGL 模块无关）。

**为什么 Hub 里显示"已安装"**：Hub 的模块状态读的是安装目录下的 `E:\Unity Hub\2022.3.62f3c1\modules.json` 里记录的**勾选清单**，不是磁盘上的实际文件。该文件里 `"webgl"` 项的 `"selected":true`（`installedSize` 2708193280 = 2.52 GB，与 Hub 界面显示的数字完全一致），所以 Hub 打勾显示"已安装"，但文件从没落到磁盘上。

旁证：同一个 `modules.json` 里 `"documentation"` 也是 `selected:true`，Hub 也显示"已安装"，而 `Editor\Data\Documentation` 目录**并不存在** —— 说明 Hub 这套显示不可信。（`zh-hans.po` 真实存在，所以"简体中文"那条是真的。）

**旁证二**：`E:\Unity Hub\` 下躺着一个 587,819,520 字节的 `UnitySetup-WebGL-Support-for-Editor-2022.3.62f3c1.exe` —— 字节数与 `modules.json` 里 webgl 的 `downloadSize` **完全一致**，说明**下载完成了，但安装器没有被执行成功**（或执行时 Unity 没关，导致解压失败）。

**后果**：`Build Settings` 的 `平台 Platform` 列表里 `WebGL` 不可选，M6 无法构建 WebGL。而交付要求里明确包含 **WebGL 链接（GitHub Pages）** —— 这一项现在做不了。

**修复（推荐：直接跑本地已下载的安装器，不用再下载）**

> 前提：**必须先完全退出 Unity 编辑器和 Unity Hub**（文件被占用会导致模块安装不完整 —— 这大概率就是当初没装上的原因）。

1. 关掉 Unity 编辑器（`Ctrl+S` 存好场景再关）、关掉 Unity Hub
2. 到 `E:\Unity Hub\` → 双击 **`UnitySetup-WebGL-Support-for-Editor-2022.3.62f3c1.exe`**（560 MB）
3. 若弹窗要求选择编辑器目录 → 选 **`E:\Unity Hub\2022.3.62f3c1\Editor`**（即含 `Unity.exe` 的那一层）
4. 等它装完（约 2.5 GB 解压）
5. 验证：`E:\Unity Hub\2022.3.62f3c1\Editor\Data\PlaybackEngines\` 下**出现 `WebGLSupport` 目录**
6. 重开 Unity → `文件` → `生成设置` → 平台列表里 `WebGL` 可选中

**备选 A（走 Hub）**：若 Hub 里 `WebGL Build Support` 那一行的勾选框是灰的（因为 Hub 认为已装），Hub 无法"移除模块"，只能走上面的手动安装器。

**备选 B（安装器报"找不到 Unity"）**：卸载该编辑器版本后重新安装，安装时勾上 `WebGL Build Support`（需重新下载 3.7 GB）。

**备选 C（安装器文件损坏）**：重新下载
`https://download.unitychina.cn/download_unity/1623fc0bbb97/TargetSupportInstaller/UnitySetup-WebGL-Support-for-Editor-2022.3.62f3c1.exe`

**✅ 已解决（2026-10-16 17:39 复核）**

用户双击运行了本地那个安装器，模块**装成功了**，但**装到了另一个编辑器**：

| 编辑器 | 路径 | 安装前 | 安装后 |
|---|---|---|---|
| 独立安装版（注册表 `Location x64` 指向的 `E:\Unity Hub`） | `E:\Unity Hub\Editor\Data\PlaybackEngines\` | 只有 windowsstandalonesupport | **多了 `WebGLSupport`** ✅ |
| Hub 管理版（项目实际使用的） | `E:\Unity Hub\2022.3.62f3c1\Editor\Data\PlaybackEngines\` | 只有 windowsstandalonesupport | 一开始**仍然没有** ❌ |

原因：安装器读注册表 `HKLM\SOFTWARE\Unity Technologies\Installer\Unity 2022.3.62f3c1` 的 `Location x64 = E:\Unity Hub`，那对应的是独立版编辑器。

**已执行的修复**：把 `WebGLSupport` 整个目录（**12380 个文件 / 2.6 GB**）复制到
`E:\Unity Hub\2022.3.62f3c1\Editor\Data\PlaybackEngines\WebGLSupport`

**完整性校验通过**：源与目标**文件数一致（12380 : 12380）**、**体积一致（2.6G : 2.6G）**，关键文件齐全 —— `modules.asset`、`WebGLPlayerBuildProgram.exe`、`UnityEditor.WebGL.Extensions.dll`、`BuildTools/Emscripten`、`BuildTools/UnityLoader`、`BuildTools/SimpleWebServer.exe`。

> 待用户在 Unity 里确认：`文件 → 生成设置` 左侧平台列表 `WebGL` 不再灰显、可选中。
> 另：独立版编辑器里那份 2.6 GB 是重复副本，可留可删（删之前需先确认，不做自动清理）。
