## 四、里程碑与工时上限

### M1 · 补齐 2 种牌面素材（上限 0.5 h）

- 产出 `star-symbol.png`、`hexagon-symbol.png`，**严格同规格**：150×200 RGBA、牌面底色 `(255,242,212)`、圆角外透明、单色图形、符号绘制区落在 x∈[18,131]、y∈[35,138] 内。
- 取色避开已用色相，避免与既有 6 张混淆：
  - `star` 金黄 `(245,170,25)`
  - `hexagon` 青 `(0,160,190)`
- 脚本：`tools/gen_symbols.py`（Pillow 绘制，可重复执行）。
- **验收**：两张图与既有 6 张并排肉眼无差异；`Counter` 主色计数确认底色一致；导入后 `Texture Type = Sprite`、`PPU = 100`。

### M2 · 牌阵改 4×4 并重算取景（上限 1 h）

- 改 `BoardManager` Inspector 序列化值：`rows = 4`、`cols = 4`、`originalY = -1`，其余不动。
- `images` 数组扩到 **8** 项并顺序固定：circle / crescent / diamond / heart / sanjiao / square / **star** / **hexagon**（顺序即牌面 ID，须与素材导入顺序一致）。
- 改相机：`size = 5.2`、`position = (0, 2.75, -10)`。
- **无需改代码逻辑**：`BuildNumbers()` 用 `k / 2` 生成，`rows*cols=16` 时自动得到 `{0,0,1,1,…,7,7}`；`PairCount = rows*cols/2 = 8` 自动正确。
- **验收**：`Tools/Memory Card/Validate Project` PASS；Play 后 `find_gameobjects` 计数 16 张；四个角牌贴边不裁切；1:1 / 4:3 / 16:9 三档 Game 视图均完整。

### M3 · 计分与步数（上限 0.5 h）

- 计分规则改为可解释的实数计分：**配对成功 +10，配对失败 −2（下限 0）**；**步数 = 每翻开第 2 张牌记 1 步**。
- `GameManager` 增 `_moves` 与 `Moves` 属性，在 `OnCardClicked` 进入第二次翻开时 `_moves++`。
- `UIManager` 增 `movesText` 字段与 `UpdateMoves(int)`；Canvas 下新增 `Text` 子物体 `MovesText`（内容 `MOVES 0`），与 `ScoreText` 同侧上下排布。
- 胜利面板 `ResultText` 改为 `TIME x.xs  SCORE n  MOVES n`。
- **验收**：一局通关后步数 ≥ 8，分数与「成功对数×10 − 失败×2」手算一致；重开后两个数值归零。

### M4 · 循环背景音乐（上限 1 h）

- 用 Python（`wave` + `math`，无需 numpy）合成 32 s、22050 Hz、单声道、16 bit 的**无缝循环**和弦铺底 `Assets/Art/bgm_loop.wav`（副歌首尾过零对齐，避免循环爆音）。
- `Sfx` 增独立 `AudioSource`（`loop = true`、`playOnAwake = true`、`volume ≈ 0.12`），与短音效的 `PlayOneShot` 源分开，避免互相打断。
- **验收**：Play 后 `AudioSource.isPlaying = true` 且 `loop = true`；连续播放 ≥ 2 个循环周期无断层爆音；短音效不打断 BGM。

### M5 · exe 构建与实机验证（上限 0.5 h）

## 五、4×4 关键参数（可直接回填）

布局公式沿用课件第 7 页：`(x, y) = (offsetX * j + originalX, offsetY * i + originalY)`

| 参数 | 3×4 现值 | **4×4 改为** |
|---|---|---|
| `rows` | 3 | **4** |
| `cols` | 4 | 4 |
| `offsetX` | 2 | 2 |
| `offsetY` | 2.5 | 2.5 |
| `originalX` | -3 | -3 |
| `originalY` | 0 | **-1** |

推导出的落点：

- 列 x = `-3, -1, 1, 3`；行 y = `-1, 1.5, 4, 6.5`
- 牌阵包围盒：x ∈ [-3.75, 3.75]，y ∈ [-2.0, 7.5]，尺寸 7.5 × 9.5，中心 (0, 2.75)
- 水平/垂直间距均为 0.5，与卡牌 1.5×2 的比例关系不变

相机：

| 参数 | 现值 | **改为** |
|---|---|---|
| `orthographicSize` | 4.5 | **5.2** |
| `position` | (0, 2.5, -10) | **(0, 2.75, -10)** |

校验：视口 y ∈ [-2.45, 7.95]，较牌阵上下各留 0.45 余量；16:9 半宽 4.62 > 3.75；4:3 半宽 6.93；1:1 半宽 5.2 —— 三档均不裁切。

> 注意：若只把相机 `size` 提到 6.0 而不下移中心，顶行仍会被切，且底部出现大片空白。**中心和尺寸必须一起改。**

## 八、两项设计决策的评估结论（2026-10-23 15:40 量化复核）

### 8.1 新增图案与配色

**结论：`五角星` 保留；第二张建议由 `六边形` 改为 `十字（加号）`；`六边形` 可作下限方案。配色 `#00A0BE`（青）可直接采用，`#F5AA19`（金）可用但为 8 色中最弱一环，建议加深至 `#C97A00`。**

依据（量化数据见回执）：形状按「凸/凹 + 对称阶数」布点，现有 6 张为**凸 4 / 凹 2**；再补凹形两张可达 **凸 4 / 凹 4** 平衡。`六边形` 属凸+全直+高填充，与 `方形`（凸+直）和 `圆形`（凸+曲）同时相邻，且小尺寸下 6 边与圆周的辨识度显著下降。

| 颜色 | 色相 H | 与最近已用色的 ΔE | 相对牌面底 `(255,242,212)` 对比度 |
|---|---|---|---|
| 现有最小值（方形 vs 菱形） | — | 36.8 | — |
| `#00A0BE` 青 | 189.5° | 33.9（vs 圆形） | 2.79 |
| `#F5AA19` 金 | 39.5° | 46.2（vs 月牙） | **1.78（偏低）** |
| `#C97A00` 深琥珀 | 36.4° | 37.4（vs 月牙） | 3.02 |

青色落在已用色相第二大的空隙（156.8°→225.7°，中点 191°）正中，与两侧各差 32.7°/36.2°，无冲突。金色与月牙橙仅差 18.8°，且饱和度/明度几乎相同（90%/96% vs 100%/100%），色相维度上确实最挤 —— 靠五角星与月牙的形状差兜底，但若追求稳妥应加深明度。

### 8.2 BGM 实现方式

**结论：采用方案 A 为主、保留现有程序化短音作为音效部分的「混合式 A」——BGM 用合成 wav 导入 + `AudioSource.loop = true`，翻牌/配对/失败/胜利音继续用现有 `Sfx` 的 `PlayOneShot`。**

依据：作业原文「掌握音频组件（AudioSource）的使用，实现背景音乐与游戏音效的播放控制」的评分落点是**组件配置**而非算法；报告要求「附截图」，A 可产出 Project 音频资源、Inspector 组件、代码三处证据，B 仅有一处代码。体积代价 32 s / 22050 Hz / 16 bit / 单声道 ≈ 1.35 MB，相对 exe 包体可忽略。风险为压缩格式在循环点产生间隙，用 WAV + `Decompress On Load` 即可规避。
